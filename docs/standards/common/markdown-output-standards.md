# Markdown Output Standards

## Purpose
Define consistent, production-quality markdown output for all workflows.

## Applies To
- All markdown artifacts generated by prompts, skills, and workflows
- Reports, plans, analyses, test outputs, and implementation notes

## Required Rules
- Use clear section headings in logical top-down order.
- Keep content concise, evidence-based, and action-oriented.
- Distinguish facts, assumptions, risks, and recommendations.
- Use stable terminology throughout a document.
- Include paths and identifiers needed for traceability.

## Formatting Rules
- Use short sections with meaningful titles.
- Use flat bullet lists; avoid nested bullets.
- Use tables only when they improve comparability.
- Keep line lengths readable and avoid noisy formatting.
- Use consistent tense and voice.

## Evidence and Traceability
- Reference concrete artifacts, files, and outcomes.
- Mark unknowns explicitly instead of inferring silently.
- Separate observed behavior from proposed changes.

## Avoid
- Generic filler text
- Contradictory statements across sections
- Hidden assumptions or undocumented scope changes

## Review Checklist
- Is the structure scannable and complete?
- Are conclusions supported by evidence?
- Are risks and assumptions explicit?
- Are outputs actionable for downstream teams?
